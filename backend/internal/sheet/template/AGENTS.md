# AGENTS.md — backend/internal/sheet/template (DAG, Registry, Templates)

## Rules

- **Templates are code, not DB** — no `template` collection; `BuildRegistry` freezes templates and DAGs at boot. `Registry.List`/`FetchByID` return deep copies; resolve DAGs through `Registry.DAG` (the `sheet.DAGProvider` interface), never a map accessor.
- **DAGs are immutable after boot** — the mutex is private. Read through `HasNode`/`GetNode`/`GetChildren`/`ValidateUpdateKeys`, or stay under the single lock `Recalculate`/`NormalizeAndRecalculate` takes. Never nest a locking call under `Recalculate` (recursive `RLock` deadlocks with a queued writer; `TestRecalculate_ValidationRunsUnderSingleReadLock`).
- **Use `NormalizeAndRecalculate` for PATCH** — one lock covers editability, exclusive normalization and recalculation. Do not compose `ValidateUpdateKeys` + `NormalizeExclusiveUpdates` + `Recalculate` in production. Unknown key/prefix → `UnknownFieldError` (400 `UNKNOWN_FIELD`); derived leaf → `NotEditableError`; non-numeric exclusive member → `ExclusiveValueTypeError`; two members on → `ExclusiveGroupConflictError`. `Create` may call `Recalculate` directly because it seeds derived fields too.
- **Keys cannot collide** — DAG keys are dotted (`stats.dexterity`); engine env keys use underscores (`stats_dexterity`). Every segment must match `^[A-Za-z][A-Za-z0-9]*$`; never relax it (`TestBuildDAG_FieldNameValidation`).
- **Change detection is relative** — `maputils.Equal` uses a 1e-9 relative epsilon, so absolute slack grows with magnitude and integers above 2^53 collapse in `float64`. Do not use it for exact currency/XP arithmetic; a no-op update cascades nothing and does not repair stale derived values.
- **Depth is capped at 5** — `maputils.FlattenPathKeys`/`ToEngineEnv` return `ErrMaxDepthExceeded`; the service maps it to 400.
- **Formulas and `DependsOn` must match** — `BuildDAG` checks declared deps exist, not that every static identifier a formula reads is declared; an undeclared static read evaluates against `0.0`. Record formulas are stricter: each own-Record read is `record_<field>` and must be declared, so the compiler rejects an undeclared one at boot. A Record dependency is a one-segment path (a shape field name, or a top-level static field name); a multi-segment path is a static Sheet field. Keep `TestTemplates_FormulaReferencesMatchDependsOn` green. Text leaves never carry formulas.
- **Aggregates are derived leaves** — `FieldSchema.Aggregate` is `{list, field, op}` with `op` `sum` or `count` (non-zero values). Boot rejects a missing list or shape field, a non-number field, an editable or formula-carrying aggregate, an unknown op and a declared `depends_on`; the dependency on `<list>.<field>` is implicit and feeds the same topological sort, so a cycle through an aggregate fails boot. An empty or missing list aggregates to 0. `aggregate.go` owns the declaration, validation and evaluation.
- **Reset actions are declared, compiled at boot** — `Template.Actions` holds `{id, label, assignments}` and each assignment is `{target, expression, filter?}`. `BuildDAGWithActions` compiles every expression and stores the action in the DAG; `BuildDAG` is the no-actions wrapper. A target is an editable `number` leaf or a list Field (`<list>.<field>`); `filter` is optional, list-only and must name a numeric shape Field (non-zero selects the Record; a list target additionally exposes only the declared `record_<field>` reads). Boot rejects duplicate or malformed ids, unknown, derived or non-editable targets, an empty or uncompilable expression and an invalid filter. `DAG.CalculateReset` evaluates all assignments against the stored Sheet under the same read lock that normalizes, applies Records and recalculates, and returns `ChangedKeys`. `reset_actions.go` owns it.
- **Seed by type** — `FieldSchema.SeedValue()` is `""` for text, `false` for bool, otherwise `Default`. The DTO `default` stays numeric for every type, so a text leaf showing `0` is expected.
- **`config` vs `rules`** — `config.*` leaves are 0/1 wiring flags (the web renders any `config` first segment as a toggle). Any other editable number leaf opts in with `Flag`; the web renders a flagged leaf as the same toggle in any path. `ValidateFlags` rejects a flag on a non-number or derived leaf and a default other than 0 or 1 at boot; PATCH, preview and create values accept only numeric 0 or 1 for a flagged leaf (`FlagValueError` → 400 `INVALID_REQUEST`). Tuning numbers live in `rules` and are read by formulas.
- **Record lists are declarations, not DAG nodes** — `FieldNode.List` holds `{Label, Columns, Capacity, Shape, Dice, NotD20}`; `BuildDAG` validates it and stores it in `DAG.lists`, and only derived shape leaves become virtual graph nodes. A list path is at most three segments, capacity is 1–200, the shape is flat leaves, and `position` is reserved; a top-level `record` field is reserved for the per-Record namespace. PATCH and preview go through `DAG.CalculateSave` (or `NormalizeAndRecalculateWithRecords` when the delta is already split) so splitting, Record application, exclusive normalization and recalculation share one read lock; `DAG.ApplyRecordUpdates` stays the standalone writer for tests, and `Create` values drop a derived Record field with `DAG.DropDerivedRecordValues` before the strict split. The id is `r` plus 32 lowercase hex characters (never `idgen`), removal wins over a same-PATCH write, and capacity is checked on the merged list. Shape flags and `max_length` are validated at boot and on every write; a derived shape leaf is still refused as a write, but its formula is compiled at boot and evaluated per Record on every save. `List.Dice` is the Row default of every Record and `List.NotD20` its not-a-d20-test marking.
- **Record scope** — a Record formula reads its own Record as `record_<field>` and the Sheet through the normal static keys; `record` is only a reserved top-level key and is never a formula input, so `record.<field>` fails boot. Every own-Record dependency is declared as one segment, every static Sheet dependency as its dotted path, and `BuildDAG` rejects a missing shape field, a missing static path and an undeclared `record_<field>` read (the compiler env exposes only declared Record fields). Exclusive groups in a shape apply per Record: two non-zero members in one Record are `ExclusiveGroupConflictError`, a chosen member clears its siblings in that Record, and two Records may choose differently.
- **Order is presentation** — `SectionOrder` and nested `Order` drive the DTO; stored layouts are keyed by name and survive a reorder. Ghost or duplicate entries are skipped; unlisted keys fall back to alphabetical.
- **Row keys mirror the web** — `SectionRowKeys` derives static Rows (lone leaf path, table group path, `<parent>#<exclusive_group>`) and `IsRowKey`/`ParseRecordRowKey` add Record Rows `<list>.<id>`; both must change with `web/src/engine/field_grouping.ts` and `web/src/engine/row_identity.ts`. A Record Row is validated from the list path and id format alone, never from Sheet data, so a stale id still saves; `position` is not a shape Field. `ValidateLayout(tmpl, sectionOrder, pinned)` takes plain lists and returns `UnknownLayoutSectionError`, `UnknownLayoutRowError` or `DuplicateLayoutKeyError`.
- **Boot validators** — `BuildRegistry` prepares the row index and runs `ValidateDiceDefaults`, `ValidateNotD20Tests`, `ValidateGenerationMetadata`, `ValidateFlags` and `ValidateNameLeaf`; `BuildDAG` runs `validateFieldNames`, `collectLists` (list declarations), the aggregate declarations, the Reset action compilation, the static formula compile, the Record formula compile and one topological sort over static, virtual Record and aggregate nodes, so a bad template, list, action or a cycle across a list fails boot. Keep the pinned `fantasy_v1` seed tests current. Dice defaults are read-only template data and are never written to a Sheet; a Section default must fit at least one Row of that Section (including a list's Record shape), a table Row needs `@.<column>` because the Row key is not a Field, and a list default is checked once against its shape.
- **Generation metadata** — `Generatable`, `GeneratableKinds` and `PreferDefault` are optional flags; `Min`/`Max`/`MaxLength` are pointers so "unset" differs from 0. `ValidateGenerationMetadata` rejects a generatable non-editable leaf, an inverted range, bounds on a non-number, a non-positive or non-text length limit and an out-of-range `PreferDefault`. Only the generation validator reads `Min`/`Max`; PATCH and preview reject an updated text leaf longer than its `MaxLength` with `TextTooLongError`.
- **Template IDs are slugs** — `FetchTemplate` rejects anything outside `^[a-z][a-z0-9_]*$` before the registry lookup, so junk is 400, not 404.
- **Errors** — declare typed errors here; never import `apperr`. Wrap with `%w`; translate at the service boundary. `ErrTemplateIDNotProvided` and `ErrTemplateIDInvalid` are 400 at both boundaries.
