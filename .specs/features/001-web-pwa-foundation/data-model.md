# Phase 1 — Data Model: Web PWA Foundation

The feature has no persisted server data. The "entities" below are the client-side structures,
configuration artifacts, and gate definitions the feature introduces; their fields come from the
functional requirements in [spec.md](./spec.md).

## ShellRegion

One of the three always-present areas of the application shell (FND-01, FND-03).

| Field | Type | Rules |
|---|---|---|
| `id` | `'navigation' \| 'content' \| 'panel'` | exactly one instance each; the id is the DOM landmark role |
| `order` | `number` | fixed 1/2/3 — `navigation` < `content` < `panel`; asserts shell order (FND-01) |
| `collapsePriority` | `number` | `panel` = 1, others unmapped; the panel is the first (and only) region hidden as the viewport narrows (FND-03) |
| `minWidth` | token ref | `navigation` 200–240 px fixed, `content` ~960 px readable measure, `panel` 280–320 px |
| `landmark` | `'nav' \| 'main' \| 'complementary'` | accessibility mapping; used by the keyboard/focus test (FND-04) |

**Invariants**: all three regions render on every declared route; collapsing the panel never removes
it from the accessibility tree when it is visible; no region renders placeholder or demo content
(FND-01) — `content` renders the designed `EmptyWorkspace` view until the catalog feature lands.

## DesignToken

A named visual value; the only sanctioned source of visual values in the client (FND-02, FND-05).

| Field | Type | Rules |
|---|---|---|
| `name` | string | `--lg-<category>-<role>` in CSS; camelCase mirror in `theme/tokens.ts` |
| `category` | `'type' \| 'space' \| 'radius' \| 'size' \| 'color' \| 'focus' \| 'hover'` | closed set; new categories require a plan amendment |
| `value` | string / number | from the ported desktop scale: type 12/13/15/17 (17 is the cap), space 4/8/12/16/24, radius 2/4, row height 32, control height 32–36 |
| `purpose` | string | one line; required so a reviewer can judge a value's role |
| `contrastPair` | token ref, optional | required for `color` foreground tokens used on a background; the pair must meet AA (FND-05) |

**Validation rules**: components MUST NOT contain literal spacing/type/radius/color values (asserted
by a rendering test that reads computed styles against the token map); every `color` token used by
the shell has a `contrastPair` and passes the contrast check (FND-05).

## DeclaredRoute

A path the client serves (FND-08).

| Field | Type | Rules |
|---|---|---|
| `path` | string | starts with `/`; unique |
| `screen` | component ref | the single screen the route renders |
| `audience` | `'public' \| 'session'` | `session` routes are gated in the auth feature; this feature declares only public routes |
| `deepLink` | `true` | every declared route is deep-linkable; verified by an E2E navigation per route |
| `notFound` | boolean | exactly one fallback route; renders the designed not-found state, never a blank page |

**State transitions**: `cold load of /path` → shell renders → router resolves `path`;
`unknown path` → `notFound` screen; `offline load of /path` → worker serves the shell → same screen.
This feature declares `/` and the not-found fallback; later features append routes.

## QualitySecurityGate

An automated check that a client pull request must pass (SEC-01…SEC-05).

| Field | Type | Rules |
|---|---|---|
| `id` | `'quality' \| 'sca' \| 'sast' \| 'secrets' \| 'lockfile'` | one job per id in `ci-web.yml` |
| `triggerPaths` | string[] | `web/**`, the workflow file, `package.json`/lockfile; plus `.specs/**` and `scripts/**` for the traceability lint |
| `blocking` | `true` | no gate may set `blocking: false` (SEC-04) |
| `failClosed` | `true` | a gate that cannot execute fails the pipeline (SEC-04) |
| `artifacts` | string[] | scanner report/SARIF where the tool produces one; referenced by the contract |
| `negativeTest` | string | the seeded input that proves the gate fails (vulnerable dependency for `sca`, a secret-like string for `secrets`) |

**Invariants**: no job carries `continue-on-error`; removing a gate or weakening `blocking`/
`failClosed` is a policy violation, not a code review preference (SEC-04).

## OfflineShellArtifact

A file the worker caches so the app boots without network access (FND-07, FND-09).

| Field | Type | Rules |
|---|---|---|
| `glob` | string | shell HTML, entry chunks, CSS, fonts (if any), icons — generated by the build's precache manifest |
| `versionIdentity` | string | build revision baked into the precache manifest; a release changes it |
| `cacheName` | string | prefixed with the version identity; previous versions are deleted on `activate` |
| `excluded` | string[] | `/auth/*`, any request carrying an authorization header, and any response marked authenticated (FND-09) |

**State transitions**: `install` → precache shell, wait; `activate` → delete caches whose prefix is
not the current version; `fetch (navigation)` → serve shell from cache when offline;
`update found` → notify the visitor → on accept, skip waiting and reload (FND-09).

## BrowserMatrixEntry

A target engine in the installability matrix (FND-06, SC-002).

| Field | Type | Rules |
|---|---|---|
| `engine` | `'chromium' \| 'firefox' \| 'webkit'` | four brands map onto these engines: Chrome/Edge → chromium, Firefox → firefox, Safari → webkit |
| `versions` | string | latest two |
| `verification` | `'automated' \| 'manual'` | `chromium` is automated in CI; the others are verified manually at each release and the result is recorded |
