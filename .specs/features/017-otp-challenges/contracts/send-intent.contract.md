# Contract: The `CodeMailer` port and the outbox additions

**Feature**: `.specs/features/017-otp-challenges/` | **Requirement IDs**: `OTP-10`, `OTP-12`,
`OTP-13` | **Owner**: `internal/auth` (the port), `internal/app` (the adapter),
`internal/email/outbox` (the store additions)

## Purpose

Record the durable intention that a code must be emailed, without the auth domain importing the
email domain, and make a resend able to re-send the *same* code by cloning the intention that already
carries it — the code's only durable home.

## The port (declared by the consumer)

```go
// CodeMailer records the durable intention that a code must be emailed.
type CodeMailer interface {
    // Record writes a new pending intention with the supplied identity, recipient,
    // template, code, lifetime and purpose.
    Record(ctx context.Context, id, to string, purpose Purpose, code string, expiresInMinutes int, now time.Time) error
    // Requeue writes a new intention carrying the same recipient, template and
    // payload as the intention identified by id, with a fresh identity, and
    // returns that new identity.
    Requeue(ctx context.Context, id string, now time.Time) (string, error)
    // SentSince counts the intentions recorded since the given instant.
    SentSince(ctx context.Context, since time.Time) (int, error)
}

var ErrSendBudgetExhausted = errors.New("daily email send budget exhausted")
```

Declared in `internal/auth`, implemented by `internal/app/email_intent.go` over
`internal/email/outbox`. `internal/auth` never imports the email domain (`R8`). The sentinel is plain
`errors.New`, like `ErrTransient`/`ErrPermanent` in the email domain: no HTTP status to map at this
layer.

## The store additions (`internal/email/outbox`)

```go
// Clone creates a new pending intention from an existing one's recipient,
// template and payload, with a fresh canonical identity, attempts = 0 and
// next_attempt_at = now. An unknown identity is ErrIntentNotFound.
Clone(ctx context.Context, id string, now time.Time) (Intent, error)

// CountSince counts intentions with created_at >= since.
CountSince(ctx context.Context, since time.Time) (int, error)
```

A new non-unique index on `email_outbox.created_at` backs `CountSince` (`shared/db/indexes.go`).

## Rules

- The intention identity is generated by the challenge service (`idgen.New`) and passed to
  `outbox.NewIntent`, which validates it (EML-18); the service therefore knows `LastIntentID` before
  `Record` is called, and the write order is account, challenge, intention last — the plan's §5.3
  order, with no compensating update (`R8`).
- `Record` maps the code into the payload as `{code, expires_in_minutes, purpose}`; the code is not
  logged, and the adapter never renders the message (the worker does).
- `Requeue` never mutates the original intention: the resend is a **new** row with a **new**
  identity, which is what stops the provider's idempotency key from suppressing the second send
  (`R3`, EML-18).
- `SentSince` is the daily cap's only input: the cap value and the day window are decided by the auth
  service (`AUTH_OTP_DAILY_SEND_CAP`), not by the store (`R6`).
- `ErrSendBudgetExhausted` is returned by the adapter when the count has reached the cap, and the
  service maps it to `EMAIL_UNAVAILABLE` (503) without recording anything (`OTP-13`).
- The request-serving process still never contacts the provider or the broker: it writes a Mongo row
  and returns (`OTP-12`).

## Invariants

- `Record` is the only way a challenge's code reaches durable storage, and it does so exactly once
  per issuance.
- A resend that records a send always writes a row whose payload is byte-identical to the original's.
- The cap is evaluated before the intention is written, so a capped request leaves the outbox
  unchanged.
- A `Record` or `Requeue` failure never leaves a challenge claiming a code it cannot re-send from a
  stored intention (the challenge stores the identity it asked the adapter to write).

## Boundary cases

| Case | Result |
|---|---|
| `Record` with a non-canonical identity | `outbox.NewIntent` rejects it (`ErrInvalidIntentID`); the service answers `INTERNAL_ERROR` and no challenge is left active (`OTP-17`) |
| `Record` fails after the challenge row exists | the challenge exists with no email; a resend re-records the same code — the plan's accepted trade-off, never a lost code (`OTP-10`) |
| `Requeue` on an identity the retention window retired | typed not-found; the service answers `INTERNAL_ERROR` (the challenge ceiling is far shorter than retention, so this is a store incident) |
| count exactly at the cap | `ErrSendBudgetExhausted`; no intention written (`OTP-13`) |
| count one below the cap | the intention is written and the count moves to the cap |
| `SentSince` with the day's start in the future (clock skew) | count 0; the guard fails open with headroom, never closed against a legitimate user |
| outbox store failure during `SentSince` | `INTERNAL_ERROR`; the request is not silently accepted (`OTP-17`) |

## Test evidence

- `internal/app/email_intent_test.go`: `Record` maps identity/recipient/template/payload; `Requeue`
  returns a fresh identity and preserves the payload; `SentSince` forwards the window; the cap
  sentinel is produced at the boundary.
- `internal/email/outbox/repository_test.go` (Mongo, self-skip): `Clone` copies payload with a new
  identity and resets attempts/eligibility; `Clone` on an unknown identity is typed; `CountSince`
  honours the range and the index exists.
- `internal/auth/challenge_service_test.go`: a fake `CodeMailer` observes the identity passed to
  `Record`, the clone on resend and the cap sentinel.
